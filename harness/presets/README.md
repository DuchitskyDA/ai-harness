# Пресеты линтера и локальный pre-commit

Пакет: правила Python (`python/code_check.py`), пресеты oxlint (`ts/index.mjs`: `base`, `reactFsd`,
`backend`) и PresetHook (`pre_commit.py`) — проверка индекса перед коммитом. Подключение ручное,
по одному репозиторию; установщик оснастки в проекты его не раскатывает.

## Что нужно

- Git (на Windows — Git for Windows: hook исполняет его `sh`, отдельный bash не нужен);
- `python` 3.10+ в PATH: hook и команды `{python}` зовут имя `python` из PATH при каждом запуске,
  абсолютный путь не сохраняется, поэтому обновление Python не требует переустановки hook;
- Node 20+ — только для TS/JS: `ts/check.mjs` и oxlint из `ts/node_modules` (TypeScript не нужен;
  `eslint` там — только библиотека для jsPlugins testing-library и vitest).

Подготовка зависимостей TS по закреплённому lock (один раз на checkout оснастки):

```sh
npm ci --prefix <checkout>/harness/presets/ts
```

Проектные линтеры (`tools/.../code_check.py` и т. п.) должны быть уже подготовлены в
самом проекте. Отсутствующий проектный линтер — ошибка проверки (код 2), не переход на более
слабый общий пресет.

## Подключение

Windows (PowerShell) и macOS/Linux — одни и те же команды, `<checkout>` — каталог оснастки:

```sh
python -X utf8 -B <checkout>/harness/presets/pre_commit.py install --cwd <repo>
python -X utf8 -B <checkout>/harness/presets/pre_commit.py check --cwd <repo>
```

`install` пишет только локальный неотслеживаемый `pre-commit` в каталоге hooks, который назвал Git
(`git rev-parse --git-path hooks/pre-commit`; учитывается `core.hooksPath` внутри репозитория,
linked worktree делят один hook). Повтор — no-op «уже подключён». Отказ с кодом 2 без записи:
внешний/общий `core.hooksPath`, `/dev/null`, symlink, отслеживаемый hook или резервная копия,
занятая резервная копия, чужой вариант harness-hook. `core.hooksPath` не перенастраивается.

Существующий hook сохраняется байт-в-байт как `pre-commit.harness-original` и вызывается первым,
если он исполняемый; его ненулевой код возвращается как есть, проверка пакета тогда не идёт.
Неисполняемый оригинал сохраняется, но не включается — Git его и раньше не запускал. Вернуть
прежнее состояние — вручную: удалить `pre-commit` и переименовать резервную копию обратно.

## Что проверяет `check`

- Файлы из `git diff --cached` (добавленные, изменённые, переименованные — по новому пути);
  текст — staged blob целиком, не рабочий файл и не HEAD. Частичный stage: в индексе нарушение,
  а в рабочей копии исправлено — коммит остановится; наоборот — пройдёт.
- Старый долг тронутого файла блокирует: baseline и вычитания прежних нарушений нет.
  Нетронутые файлы не читаются.
- Symlink, gitlink, intent-to-add и удаления пропускаются; конфликт слияния — код 2.
- Вывод: `{"checked": N, "violations": [{path, line, rule, message}]}`; коды 0 — чисто,
  1 — нарушения, 2 — проверка невозможна (stdout пуст, причина в stderr с `presets: `).
- Индекс изменился во время проверки — код 2, повтори проверку.

Размер файла (`code_lines`/`test_lines` в configs) — ориентир, при коммите не проверяется.
Правила функций (длина, сложность, вложенность, параметры, ассерты в тестах) и слои действуют.

## Configs проектов

`projects/*.json`: `default.json` плюс первый по имени файла проект, у которого совпал `match`:
`remotes` — подстрока `remote.origin.url` (без регистра, `\`, хвостовых `/` и `.git`), `dirs` —
имя основной копии. `limits` сливаются по ключу, `exclude` объединяется, прочие списки заменяются,
`lint` — объект, список или `null`. Невалидный config — код 2 с именем файла и поля.

Файл, покрытый `lint` проекта (под `lint.cwd` и `lint.paths`), проверяется только им:

- `harness-json` — `stdin_command` на каждый файл, staged текст в stdin, `{python}` = `python`
  из PATH, `{file}` — путь от `lint.cwd`;
- `oxlint-json` — `layout`: список `{dir, preset: base|reactFsd|backend, options?, ignores?}`; все файлы
  группы идут одним вызовом `ts/check.mjs`: staged тексты во временную копию, oxlint оснастки с
  конфигом из раскладки, inline-отключения (`eslint-`/`oxlint-disable`) не действуют; `command` и
  `stdin_command` не нужны. Файл вне `dir` раскладки проходит без правил.

Непокрытые Python-файлы проверяет `code_check.py` со стандартными лимитами, TS/JS — `base()`
одним вызовом Node на весь набор. Каждый внешний вызов ограничен 120 секундами.

Поверх `lint` (объекты с `cwd` и `paths`, как у `lint`):

- `formatters` — `stdin_command` с `{file}` (путь от `cwd`) на каждый покрытый staged файл, текст
  в stdin; stdout отличается от staged текста — нарушение `format` на первой отличающейся строке;
  код ≠ 0 — код 2.
- `typecheck` — `command` один раз, если staged файлы покрыты, `format`: `pyright-json` или `tsc`.
  Идёт по рабочей копии: staged текст покрытого файла не совпадает с диском (без учёта CRLF) —
  частичный stage, код 2. Нарушения — только в staged покрытых файлах, `rule` — правило pyright
  или код TS; ошибки нестейдженных соседей не блокируют.
Дополнительные проверки проекта можно оставить в прежнем hook — он вызывается первым.
